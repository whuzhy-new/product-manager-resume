# 弱表达与强表达

示例用于理解结构，不得复制其中数据到用户简历。

## 功能流水账 → 产品判断

弱：负责后台订单模块优化，完成需求分析和上线。

强：结合客服工单与运营查询，识别异常订单定位耗时的问题；补充分层筛选、异常标记与批量导出，并以人工查单时长验证效果。

## 技术堆词 → AI 产品链路

弱：使用 RAG、Agent、MCP、Memory 搭建智能助手。

强：针对知识问答引用不稳定，重构文档切分与召回策略并建立固定评测集；按“无召回、错引用、过期答案”分类迭代，保留无结果拒答与人工确认路径。

## 团队成果 → 个人贡献

弱：主导项目上线，转化率提升 12%。

强：负责支付前确认页的信息架构与实验方案；项目全量后整体转化提升 12%，其中本人模块通过点击与退出漏斗验证减少了关键信息遗漏。

## 空泛职责 → 可追问动作

弱：参与用户调研，提出优化建议。

强：访谈 8 名高频用户并归纳 3 类任务中断原因，将“入口难找”与“状态反馈不足”排为首轮问题；两项建议进入下一版本。

## 工具清单 → 使用场景

弱：熟练使用 SQL、Axure、XMind。

强：用 SQL 拆解次日留存并定位新用户首个关键动作；据此调整原型和埋点，验证引导链路变化。
