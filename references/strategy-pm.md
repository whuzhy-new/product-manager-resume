# 策略产品经理简历专项

当目标岗位或项目涉及推荐、广告、搜索、增长、定价、补贴、风控、供给分发、数据策略或实验平台时，使用本规则。

策略产品简历不是算法名词清单。它要证明候选人能从业务目标和异常中形成假设，选择可控杠杆，通过实验判断效果，并解释个人策略与最终业务结果之间的关系。

## 一条完整的策略证据链

### 1. 业务目标

先说明服务的业务、目标人群、核心矛盾和成功方向。必要时可以用一行“目标”或“OKR”总领一个岗位阶段，但它必须帮助读者理解下方项目。

合格目标通常包含：

- 服务什么业务或场域；
- 改善哪类用户、供给或客户的问题；
- 主要优化质量、规模、效率、收入还是风险；
- 有什么不可牺牲的约束或负向指标。

不要在目标行同时塞入所有技术、链路和结果，也不要把团队 OKR 直接写成个人成果。

### 2. 基线或异常

策略工作的起点应是可解释的现象：

- 某指标从 A 下降至 B；
- 某类人群明显弱于大盘；
- 某漏斗节点损耗集中；
- 某策略提升短期收益但伤害体验、生态或长期价值。

数字需说明人群、时间窗、场景和比较对象。没有可靠数字时，写清现象来源和验证方式，不制造基线。

### 3. 诊断与假设

写出如何从数据、实验、Query、访谈、工单或业务反馈中定位原因。优先表达：

- 哪个用户分层、供给分层或漏斗节点最值得优先处理；
- 表面问题与核心矛盾有什么区别；
- 排除了哪些可能原因；
- 为什么当前假设值得先验证。

“通过深度归因分析”仍然过虚，必须跟上归因对象和所得结论。

### 4. 策略杠杆与取舍

不要只写“优化模型”或“调整策略”。说明改变了什么机制，例如：

- 人群或供给分层；
- 召回、排序、过滤、频控或探索机制；
- 流量、预算、激励或权益分配；
- 审核、风控、修复或申诉链路；
- 指标体系、监控和异常处置机制。

至少解释一个关键取舍：为什么选择该杠杆、为什么暂缓其他方案、如何控制用户体验、生态、成本或风险。

### 5. 实验与灰度

上线不是验证终点。根据材料补齐：

- 实验组、对照组或可信基线；
- 样本、人群、流量和时间窗；
- 主指标、过程指标与护栏指标；
- 灰度阶段、放量条件和回滚规则；
- 全量后的长期观察与收益衰减。

流量不同时，优先比较转化率、人均值或每千次曝光收益等归一化指标，不能直接比较总量。

### 6. 结果与归因

把结果分成三层：

1. **策略直接结果**：本人负责策略影响的指标；
2. **项目整体结果**：包含其他模块共同作用的结果；
3. **业务最终结果**：GMV、消耗、收入、留存或成本等远端指标。

只有能够解释因果链时，才写“带动”或“提升”。否则使用“项目全量后观察到”“支持”“与……同期变化”等更准确表达。

## 推荐句型

句型用于检查结构，不要求机械套用。

### 异常诊断型

`针对[人群/场景]的[指标]由 A 下降至 B，通过[数据或研究方法]定位[关键原因]，将[问题]列为首轮优化重点。`

### 策略设计型

`围绕[核心矛盾]调整[分层/召回/排序/频控/分配机制]，并以[护栏指标]约束对[体验/生态/成本]的负向影响。`

### 方案取舍型

`对比[方案 A]与[方案 B]后，因[样本、成本、时效或风险]选择[方案]，先在[范围]灰度验证。`

### 实验结果型

`在[样本或流量]中完成[实验/灰度]，[直接指标]由 A 变为 B；全量后继续监控[长期指标或负向指标]。`

### 平台支撑型

`围绕[内容/用户/投放]全链路搭建[指标与监控体系]，覆盖[范围]，支持[策略迭代、异常定位或效果复盘]。`

## 内部术语的外部翻译

内部术语首次出现时，先说明产品语义，再视 JD 需要保留原词。

| 原始写法 | 对外表达重点 |
|---|---|
| 低 U、U0、分层编号 | 这类用户的行为特征、样本问题和业务价值 |
| GPM、OPM、Bonus | 优化目标、分配对象和约束，而非只写缩写 |
| One Model、LTR、召回、粗排、精排 | 改变了哪一段决策机制，为何这样选 |
| Item、SPU、类目 | 控制的是单商品、同款商品还是品类层级 |
| Combo、混排、参竞 | 多策略如何共同作用，以及候选内容进入排序的条件 |
| DA、数据看板 | 与谁协作、形成什么指标体系、支持什么决策 |

若无法准确解释术语，不要自行扩写；标记待确认并向用户追问。

## 从策略简历样例得到的正向方法

一份公开策略 PM 样例提供了以下可复用结构：

- 用一行 OKR 交代阶段目标，再拆成多个独立策略项目；
- 用“审核通过率从 64% 降至 52%”建立明确异常，再写归因和四项策略；
- 同时写短期转化与多样性、退款、结算等负向约束，说明不是单指标优化；
- 将需求分析、AB 测试、创作者访谈、看板搭建和日常复盘串成数据平台证据链；
- 让广告智能化、推荐策略、数据平台和达人运营分别证明不同能力，而不是重复一个故事。

## 同一样例暴露的风险

- **信息过密**：一个条目包含过多机制、缩写和从句，读者难以识别核心判断；
- **术语过重**：One Model、LTR、GPM、OPM、U0、Item、SPU 等未解释时只对原团队可读；
- **归因过远**：策略动作直接跳到大盘消耗、GMV 或收入，未说明其他变量和个人贡献；
- **结果模糊**：“显著提升”“预期花费上涨”“实现增长”等缺少口径；
- **所有权不一致**：同一份简历中“参与、负责、主导”并存，必须逐项目核对边界；
- **目标行过长**：OKR 同时承载背景、技术、方案和结果，反而降低扫读效率。

优化时学习它的证据链，不复制它的密度和术语。

## 不同资历的策略表达

- **实习生/应届生**：重点写独立完成的分析、局部策略、实验执行与复盘，不冒充大盘指标 Owner；
- **初中级 PM**：重点写一个策略模块的完整链路、关键取舍、灰度和上线后迭代；
- **资深 PM**：重点写目标拆解、策略组合、组织协作、指标治理和规模化机制，但仍需用具体项目举证。

## 成稿自查

1. 目标、异常、假设、策略、实验和结果是否能连成因果链；
2. 是否写清策略对象、人群和场景，而非只写模型或机制名；
3. 是否至少有一个关键取舍或负向约束；
4. 指标是否有比较对象、口径、时间窗和放量阶段；
5. 远端业务结果是否与个人策略贡献正确分层；
6. 内部术语是否已翻译成外部读者能理解的产品语义；
7. 删除算法名词后，读者是否仍能看懂候选人的产品判断。
